# The 6.1.0 sprint — retrospective, 2026-10-03

**Sprint:** Hold Speed Under Load (2026-10-01 → 2026-10-03). **Build:** v6.1.0, tag `54f7c43`, pushed 2026-10-03.
**Closeout:** `2026-10-03-HOLD-SPEED-CLOSEOUT.md`. **Plan:** `HOLD-SPEED-SPRINT-PLAN.md` (archived beside it).

## Discovered perspectives

- Holding speed under load moved the risk from the servo to the limit path: each fix that gave the drive more authority
  (D-2, D-5) exposed a mechanism that had relied on the old timidity — the blocked-stop count, the field between folds,
  the end of a long limit.
- The duty ceiling and the current fold-back are different events. Treating both as "a limiter acted" made top speed
  rough (PL-187); only the fold-back means the wheel is at its limit.
- At a low current limit the fold-back acts in single frames (10-18 % of passes), so any rule that needs a limiter on
  *every* pass never fires. A sticky "since the last tick" count is the shape that survives it.
- While a wheel is held at its limit, `drv_incr` is not the field's speed. Harness cells that read it as one were
  measuring the command, not the motor (S-b).
- Stephen's ear found PL-187 before any cell did; the log then showed it on all four wheel-directions. An attended
  observation is a real instrument when it names what it heard and where.

## Downstream impact

- **Enables:** a drive that holds speed under load and a limit path that is safe at the limit — the base the DocoEng
  motor's qualification needs. The servo model and `pasm_equiv` neutralisation are now the standard way to change the
  driver.
- **Destabilises:** the limit hold is new and certified on one motor (6.5″) and one board revision per platform. A
  second motor's different torque curve and hall timing will exercise it fresh; DocoEng must re-run the obstacle,
  grab and top-speed cells, not inherit them.
- Release archives now carry LICENSE and CHANGELOG.md (a workflow change Stephen asked for).

**Attention metric:** the task card was referenced in three of the sprint's four sessions; one session (nine starts)
shows none. Under the twice-per-task bar again — the trigger is still memory.

**The cross-reference table went stale:** eight tasks were created mid-sprint with no §15 row; reconciled only at
closeout.

**Candidates (the verdicts are Stephen's):**

1. **The cell's bound contradicts its own precondition** (PL-192). The 2026-09-26 rule (*a precondition the mechanism
   cannot erase*) is Adopted in the `plan-to-tasks` overlay and was still broken — a flagged rule broken anyway. Move it
   up a tier: from overlay prose to a point of action — the cell template's comment block states its precondition, its
   bound, and the one observation that satisfies the first and fails the second.
2. **A raised limit that another cap still governs** (PL-182). Candidate rule: when a change raises a limit, find every
   place the old limit caps the same quantity, and show the new limit reached at the desk (a scratch run) before the
   bench.
3. **A record read by position** (RC-TEL). Candidate rule (structure): the evaluation reads record fields by name from
   the log's own FIELDS line, never by counted position; a small extractor in `tools/` does it.
4. **A revision line not written when sections were added.** The sprint-plan rule is binary and coupled to the act of
   revising, and it still missed: when a visit's evaluation adds plan sections, the same edit writes the revision line.
   Candidate: put the revision-line step in BENCH-RUN-PROCESSING's "findings become plan work" step, where the act is.
5. **Tasks created mid-sprint get their §15 row in the same act** (plan-to-tasks). Candidate for the `plan-to-tasks`
   overlay: a task created after generation adds its table row before `todo_start`.
6. **Certification evidence for earlier Adopted entries:** *10-02 a safety function's premise measured at the desk* —
   applied to C4/U-1/U-2/U-5 (the model printed the per-pass fold counts before building, §4.10.3, §4.12); proposed
   **Certified**. *10-01 a dispatch's changed files checked* — the FOLLOW revert is a catch of the same kind; proposed **Certified**.
   *10-02 a fix to shipped code updates the harness copy* — the holdAtStop change updated `test_bench_rc` with the demos;
   proposed **Certified**.
